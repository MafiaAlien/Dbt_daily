### Day 1 — staging layer + ref() layering + schema tests (2026-07-28)
- Problem: build two staging views 1:1 over seeds and one mart table at customer grain, where order_count and total_amount must be 0 rather than null for customers with no orders or no captured amounts.
- Traps: (1) `sum()` over an all-null group returns null — avoided, but by accident: a `case when status = 'completed' then amount else 0 end` that was itself a requirements miss happened to supply the zero; not identified in review. - Key takeaways:
  - `count(expr)` returns 0 for a group with no non-null values; `sum(expr)` returns null for the same group — that asymmetry is exactly why `order_count` needs no `coalesce` and `total_amount` does.
  - Under a LEFT JOIN, `count(*)` counts the unmatched placeholder row, `count(<child key>)` counts real children; no `unique`/`not_null` test can tell the two apart, so only an expected-output comparison catches it.
  - dbt's built-in `relationships` test compiles a `where <column> is not null` into its child CTE: it asserts that every non-null value present exists in the parent, never that a value is present.
